# دليل التنصيب والتشغيل — منصة حجز القاعات

> كل عمليات التنصيب والتشغيل والتحديث تتم من ملف **`control app.bat`** الموجود في المجلد الرئيسي للمنظومة.
> انقر عليه نقراً مزدوجاً (سيطلب صلاحيات المسؤول) ثم اختر رقم العملية.
> قوائم الملف ورسائله **بالإنكليزية** حتى لا تظهر الحروف العربية مشوّهة في نافذة الأوامر.

---

## 1. المتطلبات

| المتطلب | الملاحظات |
|---|---|
| Windows 10 / 11 أو Windows Server 2016+ | 64-bit |
| **Node.js 20 أو أحدث** (يُنصح بـ 22 LTS) | من https://nodejs.org — النسخة LTS بالخيارات الافتراضية |
| اتصال إنترنت | **عند التنصيب والتحديث فقط** (لتنزيل الحزم). التشغيل لا يحتاج إنترنت |

لا حاجة لتنصيب PostgreSQL — قاعدة البيانات **مدمجة داخل المنظومة** (PGlite) وتُحفظ في مجلد `data`.

---

## 2. هيكل المجلد

```
hall_booking_complete\
├─ control app.bat          ← لوحة التحكم
├─ config.env               ← الإعدادات (يُنشأ تلقائياً — المنفذ 5050 افتراضياً)
├─ source_code\             ← ملفات المنظومة (تُستبدل عند التحديث)
├─ data\                    ← قاعدة البيانات  (لا تحذفه — لا يتأثر بالتحديث)
├─ backups\                 ← النسخ الاحتياطية
├─ logs\                    ← سجلات التشغيل
├─ service\                 ← ملفات خدمة ويندوز (عند التشغيل الدائم)
└─ docs\                    ← الأدلة وتقرير المراجعة
```

---

## 3. التنصيب لأول مرة

1. شغّل `control app.bat` ← اختر **[1] تنصيب كامل**.
   - يثبّت مدير الحزم pnpm (إن لم يكن موجوداً) ثم الحزم، ويبني الواجهة والخادم، ويهيئ قاعدة البيانات.
   - عند أول تهيئة تُستورد البيانات الحالية من `source_code\database\initial-data.sql` (المستخدمون، القاعات، الإعدادات، الشعار).
2. اختر طريقة التشغيل:
   - **[4]** تشغيل مؤقت في نفس النافذة (للفحص — يتوقف عند إغلاق النافذة أو Ctrl+C).
   - **[5]** تشغيل مؤقت في الخلفية (نافذة مصغّرة — أوقفه بالخيار [6]).
   - **[7]** تشغيل دائم كخدمة ويندوز — يبدأ تلقائياً مع إقلاع الجهاز ويُعاد تشغيله تلقائياً عند أي عطل.
3. افتح المتصفح على: **http://localhost:5050** (أو الخيار [13]).
4. للوصول من أجهزة الشبكة: الخيار **[15]** لفتح المنفذ في جدار الحماية، ثم **[14]** لعرض الروابط.
5. **اختصار سطح المكتب** «Hall Booking Platform» يُنشأ تلقائياً بعد التنصيب الكامل ([1]) وبعد تنصيب الخدمة ([7])، ويمكن إعادة إنشائه بالخيار **[20]**.
   - يستخدم أيقونة المنصة من `data\branding\app.ico`.
   - هذه الأيقونة هي الافتراضية، إلى أن يرفع مدير النظام أيقونة أخرى من **إعدادات النظام ← الهوية البصرية**، فتُحدَّث تلقائياً.

> **كلمات المرور:** 6 رموز على الأقل، بأي تركيبة يختارها المستخدم (أرقام فقط، حروف فقط، أو رموز). الحسابات التي تقل كلمة مرورها عن ذلك يُطلب منها تغييرها بعد الدخول.

## 4. التحديث

الخيار **[2] تحديث المنظومة** يقوم تلقائياً بـ:
1. إيقاف المنظومة (الخدمة أو التشغيل المؤقت).
2. **نسخة احتياطية تلقائية** لقاعدة البيانات في `backups\` (يُلغى التحديث إذا فشلت).
3. جلب الإصدار الجديد:
   - إذا وُجد ملف تحديث `*.zip` في مجلد `updates` يُطبَّق الأحدث تلقائياً، ثم يُنقل إلى `updates\applied`.
   - وإلا `git pull` إن كانت المنظومة منسوخة من GitHub.
   - البيانات و`config.env` والسجلات والنسخ الاحتياطية لا تتأثر.
4. تثبيت الحزم وإعادة البناء.
5. ترقية قاعدة البيانات (Migrations) دون المساس بالبيانات.
6. إعادة التشغيل بنفس الوضع السابق (الخدمة الدائمة تُعاد تشغيلها بالنسخة الجديدة، ويُفتح المتصفح).

> **طريقة التحديث:** ضع ملف التحديث في `updates`، ثم افتح `control app.bat` واختر **[2] Update** أو **[3] Rebuild** — ينفّذ كل الخطوات أعلاه في نفس النافذة، ويحدّث ملف `control app.bat` نفسه دون فتح نافذة أخرى.
>
> **تنبيه:** عند تشغيل المنظومة كخدمة دائمة، لا يكفي «إعادة البناء» وحدها لرؤية التغييرات؛ يجب إعادة تشغيل الخدمة ([10]) — والتحديث [2] يفعل ذلك تلقائياً.

**كل ملفات المنظومة داخل مجلدها فقط** (`C:\prog\hall_booking`) — لا توضع ملفات التحديث أو السكربتات خارجه.

## 5. النسخ الاحتياطي والاسترجاع

| العملية | الخيار |
|---|---|
| نسخة فورية (توقف المنظومة لثوانٍ لضمان سلامة النسخة) | **[17]** |
| استرجاع نسخة (تُحفظ البيانات الحالية باسم `pglite.before-restore-…`) | **[18]** |
| اختصار سطح المكتب بأيقونة المنصة | **[20]** |

- النسخ تُحفظ في `backups\hall-booking-*.zip`.
- قبل أي «ضبط مصنع» من شاشة الإعدادات، يأخذ الخادم **لقطة تلقائية** في `data\backups\auto-before-*.tar.gz` ويمكن استرجاعها بالخيار [18] أيضاً.
- **يُنصح بنسخ مجلد `backups` دورياً إلى جهاز أو وسيط تخزين آخر.**

## 6. الإعدادات (config.env)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 5050 | منفذ التشغيل |
| `TZ` | Asia/Baghdad | المنطقة الزمنية لمواعيد الحجوزات |
| `DB_DRIVER` | pglite | `postgres` لاستخدام خادم PostgreSQL خارجي مع `DATABASE_URL` |
| `SESSION_TTL_HOURS` | 12 | أقصى مدة للجلسة |
| `SESSION_IDLE_MINUTES` | 120 | تسجيل خروج تلقائي بعد الخمول |
| `MAX_FAILED_LOGINS` / `LOCKOUT_MINUTES` | 5 / 15 | قفل الحساب مؤقتاً بعد محاولات فاشلة |
| `TRUST_PROXY` | 0 | اجعلها 1 فقط عند النشر خلف IIS/Nginx |

بعد تعديل الملف: أعد تشغيل المنظومة (الخيار [10] للخدمة).

## 7. معالجة المشاكل

| المشكلة | الحل |
|---|---|
| «المنفذ 5050 مستخدم» | برنامج آخر يستخدم المنفذ — غيّر `PORT` في config.env أو أوقف البرنامج الآخر |
| «نسخة أخرى من الخادم تعمل» | المنظومة تعمل مسبقاً (خدمة أو مؤقت) — الخيار [12] لمعرفة الحالة |
| نسيان كلمة مرور مدير النظام | الخيار **[19]** يولّد كلمة مرور مؤقتة جديدة |
| أيقونة الاختصار لم تتغير بعد رفع أيقونة جديدة | الخيار **[20]** لإعادة إنشاء الاختصار. ويندوز يحفظ الأيقونات مؤقتاً، وقد يلزم تسجيل الخروج والدخول |
| الخدمة لا تبدأ | الخيار [16] لعرض السجلات، والتأكد من وجود .NET Framework 4 (مدمج في ويندوز 10/11) |
| تعذّر تثبيت الحزم | تأكد من الاتصال بالإنترنت وأن Node.js مثبت بالإصدار 20 أو أحدث |

## 8. للمطورين

```bash
cd source_code
pnpm install
pnpm run dev:api      # الخادم على 5050
pnpm run dev:web      # الواجهة على 5173 مع توجيه /api إلى 5050
pnpm run typecheck
pnpm run build
```

- عقد الـ API: `lib/api-spec/openapi.yaml` (توليد الكود: `pnpm --filter @workspace/api-spec run codegen`).
- مخطط قاعدة البيانات: `lib/db/src/schema` — أي تعديل يُضاف كـ Migration في `artifacts/api-server/src/db/bootstrap.ts`.
